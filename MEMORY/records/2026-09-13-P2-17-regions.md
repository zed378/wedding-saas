## What changed

Every province, regency/city, district and village in Indonesia is now in the database — **38 /
514 / 7,285 / 83,762** (91,599 rows) — with province and regency boundaries. Anyone can list them
(`GET /api/v1/regions`), and the API can say which province and regency a map pin is in
(`/regions/locate`). An event can be placed in a region at any level from a four-level picker in
the editor, and its timezone now follows the region's province exactly; a dropped pin refines the
zone from the real province boundary.

## Why

The owner asked: *"tambahkan database semua kota dan provinsi yang ada di indonesia"*, then
*"beserta kelurahan dan kecamatannya"*. The immediate use is `P2-16`'s timezone, which a province
decides and a coordinate rule only approximates.

## How

- **Source chosen and checked** — `cahyadsn/wilayah` (MIT, commit `686c3400`, files cite Kepmendagri
  No. 300.2.2-2138 Tahun 2025). Parsed both files; verified counts per level, code shapes, every
  parent present, every regency in its province's zone, and the 38 province offsets against
  ADR-070's lists. Some upstream boundary strings are not valid JSON (islands concatenated without
  a comma), so rings are extracted by pattern and containment is even-odd across all rings.
- **Importer** — `seed-data/regions/import-regions.mts` regenerates `regions.tsv` (2.2 MB),
  `regions-level-1-2.json`, `boundaries.json` (5.7 MB, simplified at 0.0005°), and refuses to write
  if any check fails. `NOTICE.md` carries the source, the changes made, and the MIT licence.
- **Database** — migration `0009` (`regions`, `region_boundaries`, `invitation_events.region_code`
  with `ON DELETE SET NULL`); the application role gets `SELECT` only. Generated by `drizzle-kit`.
- **Seed** — `seedRegions` (idempotent upsert, ~15–23 s), run by `db:seed` and by a new
  `db:seed:regions` that is allowed in production.
- **API** — `modules/regions` (repository, cached service, controller). `locate` prefilters by
  bounding box in SQL, tests polygons in the service, requires the regency to belong to the
  province, and caches by coordinates rounded to four decimals, misses included.
- **Events** — `region_code` accepted and served (owner only); `EventsService.inferZone` applies the
  spec's precedence; unknown codes are a 400 on `region_code`.
- **Editor** — `RegionPicker` (four cascading selects, searchable when long, reopening an existing
  code from its own segments), a `region` field type, `lib/regions.ts`; choosing a region sets the
  zone via `timezoneForRegionCode`; the map picker debounces a `locate` call that sets the zone and
  fills an empty or contradicted region. The reference template's event section declares
  `events.*.region_code`.

## Security Verification

- **Reference data cannot be altered by the API**: `regions.itest.ts` › "cannot be changed by the
  application role" (permission denied on `UPDATE`, value unchanged).
- **Input**: codes shape-validated before queries (`regions.itest.ts` › "refuses a malformed code %s
  before querying"); coordinates range-checked ("refuses coordinates out of range"); `region_code`
  registered `NOT_USER_TEXT` (`check-sanitized-fields`) and existence-checked
  (`events.itest.ts` › "refuses a region code that does not exist").
- **IDOR posture**: the new `:code` route has no tenant; exempted in `idor-sweep-inventory.spec.ts`
  with the test that owns its behaviour. `region_code` is written only through owner-scoped event
  routes, whose ownership tests are unchanged and pass.
- **Disclosure**: `region_code` is not in the public payload; the public DTO is assembled field by
  field and was not changed.

## Abuse Cases Covered

- Enumeration of public data — rate limit and cache.
- `locate` cost — bounding-box prefilter in SQL, simplified polygons, cached results including
  misses, rate limit.
- Malformed codes and coordinates — 400 before any query.

## Definition of Done Verification

- [x] Counts match the source — `regions-data.spec.ts` and `regions.itest.ts` › "has every level-%i region…".
- [x] Every province maps to exactly one timezone, verified against the zones' province lists — `regions.itest.ts` › "puts every province in the zone ADR-070 lists…".
- [x] Endpoints public, cached, rate-limited, and in the IDOR inventory's exemptions with a reason — cache header asserted; `general-public` guard on the controller; exemption present.
- [x] Choosing a province in the editor sets the event's timezone — `region-picker.spec.tsx` and the full-stack E2E.

## What Did Not Work

- **`JSON.parse` on upstream boundaries** — some rows are not valid JSON; switched to ring
  extraction by pattern.
- **Assuming `db:seed` could carry production reference data** — it refuses production by design;
  regions got their own command.
- **A test I wrote first described a scenario it did not test** (a point off Kalimantan while
  checking Denpasar); retitled to what it asserts.
