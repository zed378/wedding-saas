## How

**The sweeps boot the real `AppModule`.** Real guards, real repositories, real Postgres,
real Redis, `InMemoryStorage` because `NODE_ENV=test` selects it. The HTTP specs under
`test/*.spec.ts` stub their services, which is right for asserting a body schema and
useless for asserting authorization — a stub that throws `NotFoundError` proves the
controller forwards an error, not that the query was scoped.

**The route table is the inventory, not the service list.** That is the difference between
this and the per-task IDOR tests, which are all present and all at the service layer. What
no service test can catch: a route wired to a method nobody scoped, a handler that
swallows `NotFoundError` and answers a default, or an error body that names the resource
it refused.

**Four cases per endpoint**, because they fail independently:

| Case | Who | What is in the path | Expected |
|---|---|---|---|
| non-owner | Mallory | Alice's ids | 404, empty |
| cross-parent | Mallory | her own invitation, Alice's child id | 404 |
| own other wedding | Alice | her first invitation, her **second** invitation's child id | 404 |
| owner | the owner | their own | under 400 |

The third is new here and is the one that pays for itself — see What Did Not Work.

**The matrix is generated by the run**, into
`MEMORY/records/2026-09-12-P1-25-idor-matrix.md`. A hand-written matrix can claim a pass
the suite never produced, which is exactly what `MEMORY/README.md`'s honesty rule is about.

**The mass-assignment sweep asserts the column, not the status code.** Zod's default object
strips unknown keys and `.strict()` rejects them; both are safe. A sweep demanding a 422
would report a false finding against a schema that silently dropped the field. So it takes
a snapshot of every privileged column, sends twelve poisoned bodies, and compares.

## Decisions Made

| Decision | Rationale |
|---|---|
| The sweeps boot `AppModule` rather than assembling controllers | The gap they exist to close is between the route table and the service. A hand-assembled module would be another place to forget an endpoint |
| The matrix is emitted by the run, not written | It cannot then claim a result the suite did not produce |
| Rate limits are raised inside the sweeps | ~70 authenticated requests, several to `settings`, whose real policy is three a day. A 429 mid-sweep would report "not 200" as though it were "not authorised". The limiter has `rate-limit.itest.ts` |
| Mass assignment asserts the row, not the response | Strip and reject are both safe; only the write matters |
| A third vitest config for coverage | The two suites are deliberately separate, v8 coverage from two runs does not merge, and almost all service coverage comes from the integration suite — measuring either alone reports a number true of the suite and false of the code |
| `_reference` is excluded from coverage | Scaffolding, dropped from the production module graph in `app.module.ts` |
| The reorder endpoint keeps its 422 | ADR-058 — the body is a set, not an id, and indistinguishability is the property the 404 rule is actually protecting |

## Deviations from `docs/`

**One, recorded as ADR-058**: `POST /invitations/:id/gallery/reorder` answers a foreign
photo id with 422 rather than the 404 `docs/SECURITY/04` states without qualification. The
sweep asserts the stronger property instead — the answer is byte-identical to the one an
id that never existed gets.

**`docs/TESTING/04` § XSS Test step 3** — "open the public page and verify no script
executes" — is not done, because the public renderer is `P2-03`. Steps 1 and 2 are.

**`docs/TESTING/04` § Payment Tampering** is not applicable: no payment code exists yet
(Phase 3).

**`P1-22` left this card an obligation it cannot discharge**: a Playwright check at a
desktop viewport asserting the editor's three panels are visible at once. jsdom evaluates no
media queries, so every editor component test asserts the **mobile** arrangement and the
desktop layout has never been executed by anything. It is blocked on `P2-01` rather than on
effort — the wizard renders `templates={[]}` until the catalogue API exists, so no user can
create an invitation and no editor route can be opened with a session. Recorded as **DF-11**
and moved onto `P2-05`'s definition of done, which is the next card that touches the editor.
Faking a template row straight into the database to reach a shell would have produced a
green test for a path no user can take.

## Security Verification

| Control | Requirement | How it was verified |
|---|---|---|
| Object-level authorization on every `:id` endpoint | `docs/SECURITY/05`, zero tolerance | The generated matrix: 24 endpoints, non-owner 404 on all, owner under 400 on all. **Mutation**: the owner predicate removed from `ownsInvitation` — caught by **8 named tests**, including `"PATCH /invitations/:id/couple/groom answers a non-owner with 404 and no data"` |
| Two-step child scoping | `docs/SECURITY/05` § 7 | The cross-parent and own-other-wedding cases. **Mutation**: the parent constraint removed from **both** `findOwnedChild` and `updateEvent` — caught by `"PATCH /invitations/:id/events/:eventId refuses the caller's OTHER invitation's child id"` and its DELETE twin |
| No mass assignment of `owner_id`, `status`, `role` | `docs/SECURITY/05` § 3 | `"never writes owner_id, status or role from a request body"`, comparing a full column snapshot across twelve poisoned requests |
| Uploads are decided by the bytes | `docs/SECURITY/06` | `"refuses a PHP web shell renamed to .jpg, and writes nothing"`. **Mutation**: `detectFormat`'s null branch replaced with a default — caught by that test, by name |
| Stored XSS | `docs/SECURITY/08` | `"stores every free-text field with its markup stripped"`. **Mutation**: `sanitizeFields` made a no-op — caught by that test, by name |
| An error body never carries the refused resource | `docs/SECURITY/04` | Every sweep assertion searches the body for five values unique to the other tenant |

## Abuse Cases Covered

- A logged-in stranger walking ids across 24 endpoints, in every verb.
- The same stranger putting a foreign child id under a parent they legitimately own.
- A user with two weddings addressing the wrong one's rows — not a leak, a corruption.
- A client supplying `owner_id`, `role`, `status`, `id`, `user_id`, `email_verified`.
- A client naming its own `template_version_id` to pin a deprecated version (BR-3.3).
- Registration claiming `role: "super_admin"`.
- A web shell with an image extension and an image `Content-Type`.
- Markup in every free-text field the product has.

## What Did Not Work

**1. The first mutation test proved the sweep could not see the bug it was aimed at.**
Removing the parent constraint from `updateEvent` — leaving `EXISTS (… i.owner_id =
:scope)`, which checks the *event's own* invitation — changed nothing the cross-tenant
sweep could detect. Mallory is still refused; it is *Alice's own two weddings* that get
confused. The sweep was extended with a fourth case, every tenant gained a second
invitation, and the mutation is now caught by two named tests. This is the sixth time in
this project that a layer turned out to be untestable through the layer above it, and the
first time the fix was a new *case* rather than a lower-level test.

**2. The same mutation still needed both layers removed.** With only `updateEvent`
mutated, `EventsService.update` still calls `requireOwnership(findOwnedEvent(...))` first
and refuses. The sweep catches it when `findOwnedChild` **and** `updateEvent` both lose the
constraint. Worth stating plainly: the end-to-end sweep cannot replace the repository-level
tests `P1-12` added, and nothing here should be read as making them redundant.

**3. `docs/TESTING/04`'s XSS test was not in this card's step list, and nothing in the
repository had ever sent a payload through a route.** `P1-16`'s unit suite is thorough and
tests the sanitiser; a registry entry never reached by a controller would pass all of it
and store markup. Added as `"stores every free-text field with its markup stripped"`,
reading twelve columns straight out of the tables rather than through the API — a response
that re-sanitised on the way out would hide markup sitting in the row.

**4. Three positive controls failed for reasons that had nothing to do with ownership.**
The fixture inserted invitations with SQL and so had no `invitation_people` rows, which
`P1-09`'s create service writes and `CoupleService` requires (it is an UPDATE, never an
upsert, and deliberately so); the gallery attach case reused a media id already attached;
and the registration test's password — `correct horse battery staple` — is in Have I Been
Pwned, which `P1-01`'s policy consults. Each was a fixture bug that would have been read as
a finding.

**5. `pnpm add` then `pnpm remove` left a stale `vitest` link and broke an unrelated
typecheck.** Adding `@vitest/coverage-v8` changes vitest's peer-hash directory name, so
`@wi/ui` resolved one copy of vitest's types while `@testing-library/jest-dom` augmented
another — 40 errors about `toBeInTheDocument` not existing, in a package this task never
touched. `pnpm install` re-links and fixes it. Worth knowing before someone debugs the
matchers.

**6. Adding the XSS test broke the template-switch test through shared state.** It renamed
the venue the template test asserted on by literal. Fixed by capturing the events list
before the switch and comparing values after — which is a better assertion anyway, and
order-independent.

## Follow-Ups and Open Questions

- **The sweeps run nowhere automatically.** `P0-17` is still deferred (ADR-028, DF-10):
  integration tests, the coverage gate, SAST and CVE scanning run on no pipeline. These
  suites make the gate *possible* and do not make it *exist*. `TASKS/BACKLOG.md` DF-10
  already says to revisit before Phase 3 — this strengthens the case.
- **`vitest.coverage.config.mts` needs a database**, like `test:integration`. Nothing warns
  the reader except its own header comment.
- **p95 was measured against a local database with a warm pool**, which is friendlier than
  production. It is a floor, not a verdict. `P6`'s load testing is the real measurement.
- **The unauthenticated case asserts 401 for all 24 endpoints** — worth re-running after
  `requireVerifiedEmail` lands on `P3-01`/`P3-06`, since that guard adds a third refusal
  reason.
- **The editor's desktop layout is still executed by nothing** — DF-11, now on `P2-05`.
- **A new endpoint added in Phase 2 will not appear in the sweep.** The `CASES` table is
  hand-maintained. `scripts/check-id-endpoint-tests.mjs` catches a route with no test at
  all, not a route missing from this table.

## What to Watch

**The sweep's rate-limit overrides are inside the suites.** If somebody copies the
`beforeAll` into a test about limiting, the limiter will be off and the test will pass for
the wrong reason.

**The positive control creates a fresh tenant per endpoint** — 24 users, 48 invitations and
about 200 rows per run, none cleaned up until the next `resetTenantData`. Fine now; if the
case list doubles, this is where the run time goes.

**97% coverage is not 97% assurance.** The number is high because the integration suite
drives real services against a real database, which is the right reason — and a line
executed is not a line asserted. The mutation tests in this record are the part that means
something.
