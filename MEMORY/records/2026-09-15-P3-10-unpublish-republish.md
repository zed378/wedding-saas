## What changed

- **`POST /api/v1/invitations/:id/unpublish`** (`PublishController` → new `UnpublishService`): no body; owner
  lock; `published` required (422 `INVITATION_NOT_PUBLISHED`); → `paid` if history ever reached `paid`, else
  → `draft` (new USER edge `published → draft`); `published_at`, `expiry_date` and the slug untouched;
  `cache.invalidate` queued after commit; `invitation.unpublished` log.
- **Republish never adds validity** (fixes a `P3-09` gap): `PublishService.decide` keeps the stored
  `expiry_date` for a republish unless a paid order is newer than `published_at`; a passed kept date is
  `RENEWAL_REQUIRED`. `recordPublication({ keep: true })`, `expiryStillRunning`, `Entitlements.purchasedAt`.
- **Trial resume**: a never-paid draft published before may republish while its original window runs, same
  end date; after it `TRIAL_ALREADY_USED`. A refunded draft answers `PAYMENT_REQUIRED`.
- **Settings**: a post-publish slug change returns `slug_change: { previous_slug, links_broken: true }` and
  queues `cache.invalidate` for the old slug.

## Why

Card goal and BR-2.5 / BR-6.2; the three gaps in spec § 2 (ADR-081).

## How

Spec § 4 and § 8; ADR-081. Unpublish reads history under the same lock as the transition, with the same
predicate the trial rule uses.

## Security Verification

- IDOR: `unpublish.itest.ts` › "answers another user's invitation with 404, and unpublishes nothing"; sweep case
  `POST /invitations/:id/unpublish` (attack 404, owner 200).
- No free product from a trial: "unpublishes a trial to draft, never to paid" (mutation-checked).
- No free validity: "republishing keeps the expiry date it had", "refuses to resume a trial after its window"
  (mutation-checked).
- Slug squatting: "keeps the slug reserved while unpublished".
- Client input: `publish-http.spec.ts` › "refuses a target status in the body without calling the service".

## Abuse Cases Covered

Spec § 11, every row named above.

## Definition of Done Verification

- [x] Unpublish sets `paid`, never `draft` — for a paid invitation; a never-paid trial deliberately goes to `draft` (ADR-081), which is the rule's intent: never hand out what was not paid for.
- [x] 404 immediately after unpublish — repository read and E2E through the production public-invite build. **Partial**: "through the cache layer" has no cache to read through yet; obligation on `P3-12`.
- [x] Slug cannot be claimed while unpublished.
- [x] Republish requires no new order.

Global DoD: `pnpm verify` and the full integration suite were run before merge (results in the commit
message's task line and `TASKS/PROGRESS.md`); the publish E2E passed.

## What Did Not Work

- The first IDOR sweep run failed the owner control for unpublish: a fresh tenant's invitation is not
  published, so the owner got 422. Added a `prepareOwner` hook that publishes the owner's fresh invitation only;
  the attack still runs against an unpublished invitation, where a missing ownership check would answer 422
  instead of 404 and fail.
- Running the sweep without `TEST_REDIS_URL` pointed the app at the default Redis port 56379 and
  `POST /invitations/:id/media` timed out at 30 s. Not a code defect — set `TEST_REDIS_URL=redis://localhost:56279`.
- Running itests without `MIGRATION_DATABASE_URL` falls back to a testcontainer without the `wedding_app` role
  and fails in migration `0009`'s GRANT (as in `P3-06`).
- A long bash heredoc for the bookkeeping failed to parse; written with the file tool instead.
