## What Changed

Upgraded existing production dependencies within their selected major versions and installed the actual resolved packages. The production dependency audit went from 32 advisories (4 critical, 10 high, 15 moderate, 3 low) to zero. No application source, endpoint, database schema, business rule or dependency family was introduced by this lane.

## Why

The previous P5-14 verification identified known vulnerable installed dependency versions. This closes that measured dependency gate before acceptance continues; it does not introduce Phase 6 product work or claim that an audit replaces the security testing required by `docs/PLAN/17-ACCEPTANCE-CRITERIA.md`, `docs/SECURITY/05` or `docs/SECURITY/07`.

## How

Ran recursive pnpm updates targeted to existing dependency names rather than updating every workspace dependency. Updated Nest common/core/platform-express/testing together, refreshed Express, Next, Zod and sharp, then audited. Four remaining findings in the sanitizer subtree required a second targeted sanitize-html update. Its refreshed postcss/source-map-js subtree removed the final high advisory. The lockfile was generated by pnpm, not hand-edited.

## Decisions Made

Retain selected dependency majors and no broad dependency override. pnpm inserted exact release-age exceptions for the four coordinated Nest packages; these permit the named security updates while preserving the existing protection for other releases. Install-script allow/deny policy was not relaxed. Zod 4.6.7 supersedes ADR-008's 4.5.x minor selection for the oversized-collection security fix; the parent agent owns the corresponding ADR entry and shared documentation updates.

## Security Verification

The production audit proves that the registry's known-version advisory query returned no findings for this final resolved production dependency graph. It does not prove absence of unknown vulnerabilities or reachability of each original finding. No PoC or exploit was run.

Authorization/404, accepted-field whitelisting, stored-text sanitization policy, provider-authoritative payment state, upload magic-byte validation/EXIF stripping/scanning and audited state transitions were not changed in source by this lane. Existing named application tests in the parent acceptance run must establish those controls; neither an audit nor the sharp smoke newly certifies them. Sanitizer and multipart/image dependencies changed, so stored-XSS, upload-spoofing and payment/authorization regression evidence remains required from that run.

## Abuse Cases Covered

Known vulnerable package versions are removed from the resolved production graph, as measured by the final audit. No new endpoint or input creates new task-card abuse cases here. Application-level admin privilege escalation, MFA bypass, unlogged administrative writes and invitation content editing remain P5-14 parent verification responsibilities. No claim is made that dependency updates alone close those abuse cases.

Dependency audit, immutable install consistency, schema unit regressions, worker unit regressions, native image operation and scoped formatting passed. No new resource route, response envelope, stored input, write field or state transition requires a new per-endpoint test. Parent owns final complete suites, global gates, board/index/changelog and ADR synchronization. No global DoD item is waived, and this record does not mark P5-14 or Phase 5 DONE.

## What Did Not Work

One nested PowerShell discovery command expanded `$_` before child execution and failed to read manifests; direct targeted reads replaced it without writes. One inline Node audit-summary command lost quotes across shells; reading the saved JSON directly provided the evidence. The first dependency update left four sanitizer-subtree advisories, which were resolved by the second targeted update. `pnpm update sanitize-html@^2.18.0` selected and wrote the compatible latest 2.18.2, so installed/list evidence is used rather than the requested floor.
