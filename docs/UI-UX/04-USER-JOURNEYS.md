# 04 - User Journeys

## Journey: Sarah — From Zero to a Published Invitation
| Stage | Action | Emotion/Need | Risk Point |
|---|---|---|---|
| Discover | Searches "online invitation" on Google/IG ads | Skeptical, comparing options | The landing page must quickly build confidence (template quality clearly visible) |
| Explore | Browses the catalog, opens several template details | Looking for one that matches their "vibe" | Filter/category must help, not overwhelm |
| Commit | Selects a template, registers an account | Some friction is acceptable (an account is needed to save progress) | Don't ask for too much data upfront, just email+name |
| Create | Fills in data in the Editor (possibly across several sessions on different days) | Needs a sense of "progress is safely saved" | Autosave must be reliable, indicator clear |
| Validate | Previews on their own phone, sends a preview link to their partner/WO for feedback | Needs confidence before paying | The preview must be 100% representative of the final result |
| Pay | Checks out, pays | Anxious about transaction security | Trust signals (official payment logos), clear status |
| Publish | Sets the final slug, publishes | Excitement, wants to share immediately | The publish process must be quick & free of technical friction |
| Share & Monitor | Sends the link to guests, monitors incoming RSVPs | Wants to know who has confirmed | The RSVP dashboard must be easy to scan at a glance |

## Journey: Guest (Mrs. Ratna) Opening the Invitation
| Stage | Action | Need |
|---|---|---|
| Clicks the WA link | Opens the browser | Fast loading even on a weak connection |
| Sees the cover | Reads the couple's names & date | The main info is immediately visible without excessive scrolling |
| Scrolls to event info | Checks the location, time | Clear address & maps button, easy to tap |
| RSVP | Fills in the attendance form | A simple form, not too many required fields |
| Sends a message | Fills in the guestbook | Optional, not forced |

## Journey: Budi (WO) Managing Many Clients
| Stage | Action | Need |
|---|---|---|
| Login | Enters the dashboard | Sees a list of all client invitations with clear status |
| Creates a new one per client | A fast wizard | The repeated process must be efficient (not many steps each time) |
| Monitors | Checks each invitation's status | Filter by status (draft/paid/published) |
| Exports data | Retrieves RSVPs to send to a client | Easy CSV export access |
